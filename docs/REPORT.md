# 喵喵地图项目报告

喵喵地图是一款 Electron 桌面应用，围绕「发现地点、记录观察、回顾同一只猫」组织功能。云端开放观察和地图打卡的浏览，账号用于发布、管理自身内容和参与互动。

## 功能设计

| 模块 | 实现 |
| --- | --- |
| 发现地图 | Leaflet 加载高德瓦片。地图打卡保存地点、时间、描述和照片，支持列表筛选、距离计算、位置聚合和热力图。 |
| 校园识别 | `data/areas.json` 存储校园边界。加载时从 WGS84 转为 GCJ-02，选点后判断所属高校、校区和已有分区。 |
| 记录与档案 | 普通观察和地图打卡可关联账号下的固定猫咪 ID。档案时间线汇总本人记录，作者可补填地点、编辑或删除记录。 |
| 公开观察与互动 | 普通观察和地图打卡共用公开浏览入口，地图打卡支持点赞与评论。 |
| 统计面板 | 按时间、校园、品种和来源统计记录分布。用户可切换查询范围并排除校园示例。 |
| 寻猫小助手 | 校园清单直接从公开观察汇总，一般问题检索候选记录并调用 DashScope，回答可引用可定位的地图打卡。 |
| 个人档案 | 支持昵称、上传头像及恢复默认，服务端从认证会话确定资料归属。 |

旧版的猫咪图鉴和「今日寻猫」页面已由上述观察工作流取代。普通观察表单仍保留独立的「拍照识别品种」实验入口，默认处于未配置状态。

「喵喵轨迹」按发布者和猫咪档案 ID 识别同一档案，使用坐标和时间有效的打卡按观察时间连线。不同账号下的同名档案各自成组。连线之间的实际行走路线未知。

当前边界文件覆盖 12 所广州高校，保留同一校区内不相连的边界。数据主要来自 OpenStreetMap，华南理工大学广州国际校区为手工近似录入。`node scripts/build_areas.js` 可根据 OpenStreetMap 重新生成边界文件。

## 数据流

桌面页面通过 Electron IPC 调用主进程。主进程默认调用阿里云 ECS 上的喵喵 API。Nginx 将 `/meow-api/` 转发给 Node.js 服务，MySQL 保存账号、会话、记录、资料和互动，上传图片存储在服务器文件系统。Leaflet 随应用提供，高德瓦片在线加载。

本地模式改用 Electron 用户数据目录中的 JSON 和图片。数据通过备份导入导出在设备之间迁移。桌面源码保留旧版 Supabase 兼容路径。[云端部署](cloud-deployment.md)

| 表 | 用途 |
| --- | --- |
| `users`、`sessions` | 账号、密码哈希、会话令牌哈希和到期时间 |
| `entries` | 普通观察、地图打卡和猫咪档案，按账户、类型及记录 ID 区分 |
| `user_profiles` | 观察者昵称和自定义头像 |
| `uploads` | 已上传图片的归属、大小及媒体类型 |
| `likes`、`comments` | 地图打卡的点赞与评论 |

云端写入时校验记录和附件归属，更新使用原记录 ID。公开接口返回用于展示的观察字段和昵称，邮箱与档案备注保留在账号内。

## 验证与版本

`test/` 覆盖本地迁移、校园判定、资料校验和助手检索。Electron 回归使用隔离数据验证记录操作、地图定位、轨迹、登录界面和图表布局。服务端另有测试脚本检查真实 API 与 MySQL 集成。[已发布版本及源码启动方式](README.md)
