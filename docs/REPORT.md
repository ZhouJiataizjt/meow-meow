# 喵喵地图 (Meow-Meow Map) - 项目报告与设计思路

## 1. 项目概述
**喵喵地图** 是一款用于记录和分享猫咪发现地点的 Electron 桌面应用。它包含猫咪图鉴查询、猫咪记录管理和地图分享功能，默认支持本地离线使用。

### 技术栈
- **前端/主框架**: Electron, HTML5, CSS3, JavaScript (Vanilla)
- **后端/云服务**: Supabase (PostgreSQL, Auth, Storage)
- **可选在线能力**: 阿里云 DashScope (LLM)
- **进程通信**: Electron IPC (Inter-Process Communication)

---

## 2. 功能模块与设计思路

### 2.1 猫咪图鉴查询
- **功能**: 用户可以按地区或猫咪名称/品种查询相关信息。
- **设计**: 查询接口保留大模型扩展能力；未配置 API 时给出离线提示，不影响地图和本地记录功能。

### 2.2 今日寻猫推荐 (Knowledge & Recommendation)
- **功能**:
  - **按地区/名称查询**: 用户输入地区或猫咪名称，获取相关活动区域、品种和照顾信息。
  - **今日推荐**: 根据当前时间和用户所在地区，推荐适合寻找或观察猫咪的地点。
- **设计**:
  - 接入 **阿里云 DashScope (通义千问)** 大模型 API。
  - 通过构造特定的 Prompt（提示词），让 LLM 扮演猫咪信息助手返回总结性的文本。
  - **优势**: 相比传统数据库查询，LLM 能提供更灵活、更人性化的自然语言回答。

### 2.3 我的猫咪记录 (Personal Records)
- **功能**: 用户可以添加、查看、修改和删除猫咪发现记录（文本+图片）。
- **设计**:
  - **双模存储**: 支持本地 JSON 文件存储（离线可用）和 Supabase 云端存储（登录后同步）。
  - **鲁棒的更新机制**: 针对云端数据库权限策略（RLS）可能导致的直接更新失败问题，实现了自动降级策略即当 UPDATE 操作因权限被拒绝时，自动尝试删除旧记录 + 插入新记录的原子操作，确保用户修改能够成功保存。
  - **数据一致性**: 强化了前端与后端的数据类型校验（如时间格式、数字类型），防止因格式不匹配导致的静默失败。

### 2.4 喵喵地图 (Cat Map)
- **功能**: 一个基于地理位置的猫咪记录地图。用户可以在地图上分享猫咪出现地点，查看记录，并进行点赞和评论。
- **设计**:
  - **地图引擎**: 使用 Leaflet.js 展示地图和标记点，支持高德地图瓦片源。
  - **高级筛选与交互**:
    - **多维筛选**: 实现了只看我的快速过滤和日期范围筛选，帮助用户在海量记录中快速定位。
    - **UI/UX 优化**: 重新设计了记录列表界面，采用现代化的卡片式布局，统一了筛选控件的视觉风格（胶囊样式），提升了操作的直观性和美观度。
  - **社交互动**:
    - **点赞/评论**: 数据实时存储于 Supabase 的 likes 和 comments 表。
    - **个人资料**: 用户可以设置昵称和头像，这些信息会在评论区和记录详情中展示。

### 2.5 用户系统 (User System)
- **功能**: 注册、登录、个人信息管理。
- **设计**:
  - 基于 **Supabase Auth** 实现安全的身份认证。
  - **个人资料**: 独立的 profiles 表存储用户昵称和头像，通过 RLS (Row Level Security) 策略保障数据安全（用户只能修改自己的资料）。

## 3. 关键技术实现

### 3.1 进程间通信 (IPC)
项目大量使用了 Electron 的 ipcMain 和 ipcRenderer。前端页面不直接操作数据库或文件系统，而是发送 IPC 消息给主进程，主进程处理完毕后返回结果。这种架构提高了应用的安全性。

### 3.2 网络弹性设计
针对国内访问 Supabase 可能不稳定的情况，封装了 supabaseWithRetry 函数。
- **机制**: 当请求失败或超时时，自动进行指数退避重试（Exponential Backoff）。
- **效果**: 显著降低了因网络波动导致的请求失败率，提升了用户体验。

### 3.3 数据库操作的容错处理
在处理 update_record 等关键操作时，引入了多层保障机制：
1.  **所有权检查**: 在操作前校验记录的 user_id，防止越权操作。
2.  **执行结果验证**: 操作后检查受影响行数，若为 0 则视为失败并抛出具体错误。
3.  **策略回退**: 针对 RLS 策略限制，自动切换操作方式（Update -> Delete+Insert），最大程度保证业务功能的可用性。

### 3.4 数据库设计 (Schema)
主要数据表结构：
- profiles: 用户资料 (id, username, avatar_url)
- map_records: 地图记录 (id, lat, lng, title, images[], user_id)
- likes: 点赞关联 (record_id, user_id)
- comments: 评论数据 (record_id, user_id, content)
- **外键约束**: 严格的外键约束（Foreign Keys）确保了数据的一致性（例如删除用户会自动清理其关联的评论）。

---

## 4. 总结
本项目通过结合 Electron 的跨平台能力、本地 JSON 存储以及可选的 Supabase 云端服务，构建了一个以猫咪地图为核心的桌面应用。智能识别模块已移除，避免继续依赖与当前主题不匹配的历史模型；后续仍可独立接入猫咪识别模型。
